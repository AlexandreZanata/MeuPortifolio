# Architecture

This document explains how the site is put together and why. Individual decisions are
recorded in [adr/](adr); this is the map that connects them.

## Rendering model

The site is **fully static**. `next build` runs with `output: 'export'` and writes plain
files to `out/`: one `index.html` per page and locale, their CSS and JavaScript, fonts,
illustrations, `sitemap.xml` and `robots.txt`. There is no server, database, API route or
runtime environment variable. Anything that would need a request-time server is
unavailable by construction ([ADR 0001](adr/0001-next-static-export.md)).

| Concern                         | Where it happens                                                    |
| ------------------------------- | ------------------------------------------------------------------- |
| Routing, HTML, metadata         | Build time, in Server Components                                    |
| Translations                    | Build time; dictionaries never ship to the browser                  |
| GitHub data                     | Before the build, by a script that writes a committed JSON snapshot |
| Illustrations and social images | Before the build, by scripts that write committed files             |
| Interactivity                   | Five small Client Components (see below)                            |

### Server and client boundary

Every component is a Server Component unless it needs the browser. The client ones are
leaves, and they receive plain strings as props:

| Component                         | Why it runs in the browser                    |
| --------------------------------- | --------------------------------------------- |
| `components/layout/nav-link`      | Marks the current section with `aria-current` |
| `components/layout/locale-switch` | Links to the same page in the other language  |
| `components/layout/mobile-nav`    | Opens and closes the native `<dialog>` menu   |
| `features/lab/cnpj-playground`    | The one interactive experiment                |
| `features/resume/print-button`    | Calls `window.print()`                        |

There is no global state, no data fetching on the client and no context provider.

## Layers

```text
lib, i18n   framework-free helpers, locales, route builders, dictionaries
   ↓
content     typed facts: profile, projects, open-source list, GitHub snapshot
   ↓
components  UI primitives (ui/) and the site shell (layout/)
   ↓
features    page sections grouped by domain: home, projects, open-source, lab, resume, github
   ↓
app         routes, layouts, metadata files, global CSS
```

A file may import from its own layer and from the layers above it in this list, never from
the ones below. `eslint.config.mjs` enforces this with `no-restricted-imports`, and
`import/no-cycle` forbids cycles inside a layer.

Guidelines that keep the layers honest:

- **`app/`** composes. A page file resolves the locale, builds metadata and arranges
  feature components. It holds no business logic.
- **`features/`** owns anything specific to one area. A component moves to `components/`
  only when a second, unrelated feature needs it.
- **`components/ui/`** knows nothing about projects, locales or routes. Its components
  take explicit props and render markup.
- **`content/`** is data and types only. No JSX.
- **`lib/`** functions are pure and unit-tested.

## Content model

Content is TypeScript, not Markdown ([ADR 0002](adr/0002-typed-content-over-mdx.md)).

- `content/projects/<slug>.ts` exports a `Project`: language-independent `meta` and one
  `CaseStudy` per locale. The `Localized<T>` type makes a missing translation a compile
  error.
- A case study has a fixed shape: context, problem, decisions, implementation, challenges,
  evidence. Every project page therefore has the same structure, and the rendering code
  has no conditionals per project.
- `content/profile.ts` holds personal facts. Unconfirmed ones are `pending('note')`; see
  [CONTENT.md](CONTENT.md).
- `content/github/snapshot.json` is generated by `scripts/update-github-snapshot.ts` and
  validated by `features/github/snapshot.ts` when the module loads
  ([ADR 0004](adr/0004-github-snapshot.md)).

## Internationalisation

Locales are URL segments: `/en/...` and `/pt-br/...`, with the same slugs in both
([ADR 0003](adr/0003-i18n-routing.md)).

- `i18n/config.ts` is the list of locales and their `lang`, `hreflang` and Open Graph tags.
- `i18n/routes.ts` builds every internal URL. Components never concatenate paths.
- `i18n/dictionaries/en.ts` defines the `Dictionary` type; other locales must satisfy it.
- `lib/seo.ts` produces canonical URLs, `hreflang` alternates and social metadata for
  every page from one function.
- `/` cannot negotiate a language on a static host. It is a tiny page that forwards by
  browser language, with a meta refresh and plain links as fallbacks.

## Styling

Tailwind CSS 4, configured in CSS. `app/globals.css` declares the design tokens in
`@theme`; the default palette, radii and shadows are reset there, so only system values
exist as utilities. A handful of semantic utilities (`container-page`, `label`, `display`,
`link`) are defined with `@utility`. See [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

## Conventions

- **Files** are `kebab-case`; components are `PascalCase` named exports. No default
  exports outside the files Next.js requires.
- **Imports** use the `@/` alias across layers and relative paths inside a folder. Type
  imports use `import type` or inline `type` (enforced).
- **Props** are explicit and `readonly`. Components do not take a catch-all `...props`
  unless they wrap a single HTML element.
- **Links** go through `SmartLink`, which decides between the router and a plain anchor
  and applies the external-link policy in one place.
- **No effect without a reason**: the only `useEffect` closes the mobile menu on route
  change, and it is commented.
- **Errors**: content problems are build failures (type errors, a throwing validator, a
  failing test), not runtime states. There is nothing to recover from at runtime.

## Principles, applied with judgement

- **KISS / YAGNI** decide most things here: no CMS, no MDX pipeline, no state library, no
  animation library, no component kit. Each would add more to maintain than it removes.
- **DRY** applies to knowledge, not to markup. Routes, SEO metadata, tokens and the
  external-link policy each have one home. Two pages that happen to share a few utility
  classes are not abstracted until a third needs the same thing.
- **Single responsibility** shapes the layers and the content/presentation split. It is
  not applied to the point of one-line components.
- **Open/closed** shows up in the content model: adding a project means adding a file,
  not editing rendering code.

## Testing

| Level           | Tool                             | What it protects                                                                                                                             |
| --------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit            | Vitest                           | Route builders, SEO metadata, rich-text tokenizer, snapshot validation, CNPJ check digits, content integrity in both locales, token contrast |
| Browser         | Playwright                       | Navigation, keyboard use, the mobile menu, language switching, the lab widget, metadata, sitemap, no horizontal overflow from 320 to 1920 px |
| Accessibility   | axe-core in Playwright           | WCAG 2.2 A and AA rules on every page in both locales                                                                                        |
| Lab performance | Lighthouse CI                    | Category scores and Core Web Vitals proxies on key pages                                                                                     |
| Size            | `scripts/check-bundle-budget.ts` | Per-page transfer budgets                                                                                                                    |

Coverage is not measured as a percentage. The rule is that logic with branches has unit
tests and every page type is exercised in a browser.

## Security and privacy

- No secrets exist in the project; the only token is the CI-provided `GITHUB_TOKEN` used
  by the snapshot script.
- No cookies, analytics, third-party scripts, fonts or embeds. Every byte is same-origin.
- Response headers, including a Content Security Policy, are defined in `public/_headers`
  and mirrored for nginx in [DEPLOYMENT.md](DEPLOYMENT.md).
- External data (the GitHub snapshot) is validated before use and reviewed as a pull
  request before it reaches the site.
- Contact is a `mailto:` link, not a form ([ADR 0006](adr/0006-mailto-over-contact-form.md)).
